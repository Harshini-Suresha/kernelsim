Be the scheduler

Be the pager

You are the virtual-memory manager. Hits and empty frames are handled for you. When a page fault finds every frame full, you choose which page to evict. Fewer faults is better. The future is hidden unless you choose to peek, and the hint shows what the optimal policy would evict.

OS crash lab

Something is broken. Reproduce the bug, then choose a fix. Every outcome comes from running a simulation, so a plausible-sounding fix can still fail.

Bug detective

A system is misbehaving. Read the monitor output, then name the bug. Each case is generated by running a real simulation, so the numbers change every time. Wrong answers are worth learning from: some of these look alike.

What is inside




Processes and PCBs
Process creation, process-control blocks and the full state-transition cycle.


CPU scheduling
FCFS, SJF, Priority, Round Robin and Multilevel Feedback Queue, with Gantt traces and comparisons of waiting, turnaround and response time, throughput and CPU utilisation.


Virtual memory
Paging, page-table address translation, page-fault handling, and FIFO, LRU and Optimal replacement with fault-rate and utilisation analysis.


Concurrency
Threads, mutexes and semaphores. Race conditions, critical sections, deadlock scenarios and shared-resource coordination.


Inter-process communication
Pipes, shared memory and message queues for exchanging data between isolated processes.


File management
File creation, reads and writes, directory structures, file allocation and controlled access to storage.

Multiprogramming and CPU utilisation


If each process spends a fraction p of its time waiting for I/O, n processes in memory keep the CPU busy about 1 − pn of the time. More processes hide more I/O wait, with diminishing returns.

Choosing a page size


Small pages waste little inside the last page but need a large page table. Large pages do the opposite. The best size sits where the two costs meet, near the square root of 2 × process size × entry size.

Parallel speedup (Amdahl's law)


The serial part of a program limits what extra cores can do. A program that is 95% parallel never gets past 20 times faster, however many cores you add.

Flat vs two-level page tables


With 32-bit addresses, 4 KB pages and 4-byte entries, a flat page table always costs 4 MB. A two-level table only allocates the second-level tables a process actually uses.




Flat tableTwo-level table


Assumes the mapped memory is contiguous. Two-level tables win until nearly the whole address space is in use.
